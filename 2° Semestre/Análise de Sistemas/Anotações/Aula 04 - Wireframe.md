# 4. Wireframe 

## 4.1 Definição de Wireframe

O Wireframe é outra ferramente, seu objetivo é no apoio de levantamente e entedimento dos requisitos. Ela é uma ferramenta muito fácil de se utilizar. Ela é utilizada junto com a validação do usuário para trazer uma representação de baixa fidelidade (como se fosse um rascunho) de como será a visualização do seu projeto. Ela foca apenas em mostrar as funcionalidades, por isso, as cores mais predominantes são o preto e o branco para não influenciar na escolha do cliente. 

Em outras palavras, o Wireframe é uma representação visual de baixa fidelidade com o objetivo de mostrar ao cliente quais seram as funcionalidades que terão no seu projeto. Define a hierarquia de informações, funcionalidades básicas e a estrutura da aplicação, sem muitos elementos visuais, como cores, imagens e afins, para não influenciar na escolha do usuário.

O wireframe é considerado como uma ferramente de comunicação e planejamento, pois permite visualizar os seguintes itens:
- Estrutura da página - organização espacial dos elementos
- Hierarquia de conteúdo - prioriza e agrupa lógicamente as informações
- Funcionalidades - elementos interativos e seus comportamentos esperados
- Navegação - Fluxo de interações entre navegações entre telas ou seções

## 4.2 Fluxo de Prototipação

Primeiro começamos com o **Wireframe**, que seria toda a estrutura da visualização para o cliente, utilizando representações de baixa fidelidade e desenhos apenas para mostrar as funcionalidades. Após isso vamos para a parte de **Protótipo de Tela**, que seria um desenho já em alta resolução, com todas as cores e funcionalidades do cliente, para que no fim, se torne a **Protótipo Funcional**, que seria a aplicação feita com todos os requisitos básicos.

## 4.3 Design de Interface

O projeto identifica todos as ações e objetos da interface e realiza um layout para atender todas essas ações e objetos para a criação do protótipo de interface. O projeto de interface cria a principal comunicação entre o usuário e o sistema. 

Algumas tópicos e dicas para o Design de Interface: 
- Agrupamentos - Os elementos relacionados, precisam ficar juntos, enquanto aqueles elementos que são de outro assunto, ou que não tão relacionados com os demais elementos, precisam ficar separados.
- Proximidade do objetos (Labels) - Você pode colocar os seus labels de duas maneiras:
	- A esquerda - Ela precisa de mais espaço na vertical (logo, precisa de mais espaço na horizontal), e requer bastante atenção do usuário. Em contra partida, ela não é uma boa escolha para formulários de muitas linhas e também é mais lendo de preencher.
	- Superior - Essa é uma boa escolha para mobile e para telas responsivas, possui um ótimo suporte para muitas linhas e o usuário preenche mais rápido. Entre tanto, precisa de mais espaço na vertical e não é muito bom para formulários muito longos. 
- Descrição dos Labels - Os textos precisam ser curtos e objetivos, não precisam ser uma caixa de ajuda especificando o que o usuário deve fazer, normalmente possui apenas duas ou uma palavra. 
- Uso de hint e texto de ajuda - São links utéis que, caso o usuário precise de ajuda, eles o levam para outra página ou criam um pop-up para ajuda-lo. Caso o texto seja mas curto, você pode colocar abaixo da caixa de texto. 
- Máscaras e Campos default - As máscaras devem sempre ser utilizadas se possível, seguindo as convenções de cada caixa de texto. As máscaras ajudam a realizar o cadastro corretamente e diminuiem a margem para o erro. Caso um campo possa ser preenchido automaticamente, faça isso. Isso ajuda o usuário e poupa tempo o cadastro. 

## 4.4 Regras de Ouro da Usabilidade

### 4.4.1 Deixa o usuário no comando

Defina modos de interação que não faça o usuário usar ações desnecessárias ou que forçam o usuário a realizar alguma coisa. Prefira economizar na quantidade de clique do usuário, opções claras, automatize alguns processos e deixe personalizavél na vontade do usuário).

Além disso, possibilite que a interação do usuário possa ser desfeitas e revertidas. E, simplifique todas as interações do usuário, e permite que ela personalize as interações.

### 4.4.2 Reduza a carga de memória do usuário 

Defina atalhos intuitivos e informações de maneira progressiva. Defina defautls com significado para o seu cliente, além disso, o layout visual deve ser uma metáfora do mundo real.

### 4.4.3 Tornar a interface consistente

Matenha a consistencia ao longo de uma família de aplicações, permita que o usuário insira a tarefa atual em um contexto significativo e uma vez que a interface gere uma boa experiência para o usuário, não faça alterações, a menos que precise. 

## 4.5 Lista de Dados

As listas de dados são informações que eu irei armazenar sobre todo o meu fluxo de dados. Precisam ser importantes e estar dentro da regra de negócio do meu sistema. Em outras palavras, a listagem de dados são todos os atributos que eu irei listar das minhas entidades.
